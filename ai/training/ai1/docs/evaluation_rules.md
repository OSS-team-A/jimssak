# 짐싹 AI1 평가 규칙 (학습 전에 고정)

고정일: 2026-11-24. 이 문서와 `configs/pipeline_default.yaml`, `configs/taxonomy.yaml`을 바꾸면
비교 결과에 그 사실과 이유를 적는다. 최종 test 영상은 설정을 고정한 뒤 **한 번** 평가한다.

## 0. 용어

| 용어 | 정의 |
|---|---|
| 개별 운반 대상 | 현재 형태 그대로, 방향을 바꿔도 **내부 60×40×40cm 실험용 박스 한 개**에 넣고 닫기 어려운 실물. 실험 기준이다. |
| AI1 출력 | **개별 운반 후보 목록**. 물품 인식·마스크·추적만 한다. 치수·박스 적합(box_fit)은 판정하지 않는다(`box_fit=unknown`). 화면 면적으로 크기를 판정하지 않는다. |
| 박스 적합 판정 | AI2 또는 사람이 실측한 결과. `templates/box_fit_predictions.csv` 형식으로 받는다. |
| track_id | 한 실행 안에서만 유효한 **임시 추적 번호**. 같은 실물이 다시 나오면 다른 번호가 될 수 있다. |
| 확인 필요(needs_review) | 자동 집계에 넣지 않고 사람에게 확인을 요청한 예측. |

## 1. 데이터 사용 원칙

- `언니방영상.mp4`(video_id 예: `unnie_room_01`)는 **개발·오류 분석 전용**이다. 이 영상 및 같은 방·같은 실물의 영상에서
  뽑은 프레임은 학습에 써도 되지만, 성능 개선을 입증하는 **최종 test에는 넣지 않는다**(`make_split.py`의 `role=dev`).
- train/val/test는 프레임 무작위가 아니라 **방·촬영 세션·실물 그룹** 단위로 나눈다(`data_tools/make_split.py`).
- 독립 test 영상이 1편이면 모든 결과는 **예비 결과**로 표시한다. 임의의 정답·수치는 만들지 않는다.

## 2. 비교 대상 (같은 최종 test 영상·같은 정답·같은 채점 규칙)

| 버전 | 검출 가중치 | 추적 | 목록 집계 | 재등장 연결 |
|---|---|---|---|---|
| **B0** | 사전 학습 `yolo11n-seg.pt` (COCO) | Ultralytics 기본 BoT-SORT (`botsort.yaml`, 설치 패키지 그대로) | `pipeline_default.yaml` listing | 끔 |
| **B1** | 파인튜닝 가중치 (`train.py`의 best.pt) | B0와 동일 | B0와 동일 | 끔 |
| **B2** | B1과 동일 | B0와 동일 | B0와 동일 | **켬** (`link_reappearance.py`) |

학습할 이유가 없거나 진행할 수 없으면 B1은 '미실행'으로 표시하고, **B0 가중치를 고정한 채 재등장 연결 끔/켬**만 비교한다
(`runs/B0/<run>` vs `runs/B0/<run>/relink_*`).

ChatGPT(채팅창) 비교는 별도 행으로, 입력 방식 차이(영상 업로드 / 제공 프레임 수)를 표에 명시한다.

## 3. 프레임 인식·분할 (A)

- 사람이 만든 정답 박스·마스크가 있는 평가 프레임(test 분할)으로 `evaluate_frames.py`를 실행한다.
- 지표: box mAP50–95, mask mAP50–95 (COCO 101점 보간, IoU 0.50:0.05:0.95), 품목별 Recall(IoU≥0.5, conf≥0.25), 품목별 정답 인스턴스 수.
- 클래스 매핑은 `taxonomy.yaml`만 사용한다. B0는 COCO 클래스 중 **동일 개념**만 매핑하고, 미지원 품목은 예측이 없으므로 AP=0으로 계산된다.
- 두 가지 점수를 따로 보고한다.
  - **공통 품목**(`--common-classes`: B0·B1이 모두 지원하는 품목): 기존에 잘 잡히던 품목의 성능이 떨어지지 않았는지.
  - **전체 정답 품목**: 새 품목 지원 효과 포함.
- 정답에 마스크(다각형)가 없으면 mask mAP는 **미측정**. YOLO confidence는 정확도·Recall로 쓰지 않는다.

## 4. 최종 물품 목록 (B) — 발표 핵심 지표

### 4.1 입력
- 정답: `ground_truth_items.csv` (실제 물건 한 개당 한 행, 사람이 영상을 보고 **모델 출력을 보기 전에** 작성).
- 매칭 근거: `match_review.csv` (예측 한 행마다 사람이 근거 이미지·시각을 보고 `gt_item_id` 기입).
- 검수 중 모델이 찾은 실물이 정답 목록에서 빠져 있었음을 발견하면, 정답 CSV에 추가하고 `note`에 `검수 중 추가`라고 적는다(추가 건수 보고).

### 4.2 채점 범위
| 모드 | 정답 대상 | 예측 |
|---|---|---|
| `list` (물품 목록만) | `box_fit=no_fit` 실물 | 자동 확정(confirmed) 예측 전부. `fits`/`unknown` 실물에 연결된 예측은 **범위 외**(TP/FP 아님, 건수 별도) |
| `box` (박스 필터 포함) | `box_fit=no_fit` 실물 | 예측 중 박스 판정이 `no_fit`인 것만. `fits` 실물에 연결되면 FP(박스 적합 오판) |

AI1 단독은 박스 판정이 없으므로 `box` 모드는 **미실행**으로 표시된다. `box_fit=unknown` 정답은 대상 집합에서 빼고 `gt_box_fit_unknown.csv`로 따로 남긴다.

### 4.3 판정 (예측을 첫 등장 시각 순으로 처리)
| 상황 | 판정 |
|---|---|
| 맞는 실물·맞는 품목에 처음 연결 | **TP** |
| 이미 TP로 연결된 실물에 또 연결 | **FP(중복)** — 재등장 중복 |
| 실재하지 않는 물체 / 대상 외 오검출 (`gt_item_id` 빈칸) | **FP(오검출)** |
| 품목이 다름 (예: 책상을 table로) | **FP(클래스 혼동)**, 그 실물은 다른 TP가 없으면 **FN** |
| 한 예측이 여러 실물을 덮음 (`extra_gt_item_ids`) | **잘못된 병합** 건수 += 추가 실물 수. 추가 실물은 TP가 되지 않음 |
| 실물에 연결된 자동 확정 예측이 없음 | **FN(누락)** — 원인 힌트: 미지원 품목 / 클래스 혼동 / 잘못된 병합 / 확인 필요로만 존재 |
| `status=needs_review` 예측 | 자동 목록에서 제외 → TP도 FP도 아님. 확인 요청 건수와 그중 실제 대상 수를 따로 보고 |
| 검수되지 않은 예측 | FP(미검수), 해당 영상 F1은 **판정 불가** |

- 보고: TP/FP/FN 원시 건수, Precision, Recall, F1, 중복 수, 잘못된 병합 수, 확인 요청 수.
- 의자 A를 두 번 세고 B를 놓치면 총수는 같아도 TP1·FP1(중복)·FN1이다.

### 4.4 수량 절대오차
- 영상×품목별 `|예측 수량 − 실제 수량|`.
- **평균 범위(고정)**: 각 영상에서 (정답 대상 품목 ∪ 예측 품목)의 모든 영상×품목 쌍. 평균은 이 쌍들의 단순 평균(MAE).
- ChatGPT 답변이 합계만 주면 수량 오차는 계산하고, 실물 매칭 기반 F1·중복 원인은 **판정 불가**로 둔다.

### 4.5 재등장 연결(B2) 채점
- 단일 트랙 물품은 B0 검수표(`T#####`)를 그대로 쓴다.
- 여러 트랙을 묶은 물품(`G#####`)은 구성 트랙의 검수에서 유도한다. 모두 같은 실물이면 그 실물, 서로 다르면
  프레임이 가장 많은 트랙의 실물을 대표로 하고 나머지는 **잘못된 병합**.
- 판정 순서: ① 지원 품목 누락이 줄었는가 ② 목록 F1·수량 오차가 좋아졌는가 ③ 중복을 줄이면서 서로 다른 물건을 더 많이 합치지는 않았는가.
  좋아진 품목과 나빠진 품목을 모두 남긴다.

## 5. 운영 효율 (C)

- 같은 GPU에서 **초기 로딩(모델 로드+워밍업)** 과 **영상 처리**(디코딩/검출·분할/추적/기록·저장/목록 집계)를 분리 기록한다(`run_manifest.json`의 `timing`).
- 영상 길이, 처리 프레임 수, 장치·GPU 이름을 함께 기록한다. 여러 영상이면 편당 중앙값과 범위(`summarize_runs.py`).
- GPU 추론비는 단가와 '실제로 과금된다고 가정한 시간'을 명시할 때만 환산한다(`--gpu-hourly-cost`, `--cost-basis`).
  연구실 이용료·운영 추정비·상시 서버 유휴 비용은 섞지 않는다. ChatGPT 채팅은 사용 방식만 기록하고 편당 API 비용은 미측정.
- CPU에서 잰 시간은 서버 GPU 시간이 아니다.

## 5-1. 자동 파이프라인 확장 단계 (2026-11-25 추가, 학습 전에 고정)

| 단계 | 기준선 | 개선 | 평가 데이터(학습과 분리) | 주 지표 |
|---|---|---|---|---|
| B1 탐지·분할 | COCO 사전학습 yolo11n-seg | LVIS 이사 물품 파인튜닝 yolo11n/s(-m)-seg (val mask mAP로 선택) | LVIS val 중 **COCO val2017 이미지만**(B0 사전학습 미사용 이미지) | 공통/신규 클래스 분리 box·mask mAP50-95, P/R/F1, FP/FN, 혼동행렬, IoU/Dice |
| B2 추적·재식별 | BoT-SORT, 재등장 연결 없음 | ByteTrack 비교, 색 히스토그램 규칙, DINOv2, triplet 학습 헤드 | 합성 카메라 이동 영상(LVIS 테스트 이미지), ABO 테스트 상품 | HOTA·IDF1·IDSW, 물품 F1·중복률·잘못된 병합률·재등장 연결 정확도, 검색 Recall@1·mAP |
| B3 전후 매칭 | 클래스별 수량만 비교 | 임베딩 + 코사인 + Hungarian (val 시나리오로 임계값 선택) | ABO 테스트 상품 합성 시나리오 | 분실 의심 P/R/F1, 정상 오탐률, 누락률, 매칭 정확도 |
| B4 손상 | COCO 모델(crack 미지원), 전역 kNN, 픽셀 차이 | crack-seg 파인튜닝, PatchCore, 정합+특징 차이 | crack-seg test, VisA test, ABO 합성 손상 쌍 | mask mAP·IoU·Dice·P/R/F1, 이미지/픽셀 AUROC, 신규 손상 F1·영역 IoU·조명 변화 오탐률 |

- 언니방영상은 학습에 쓰지 않고, B0·B1·B2 추론 결과와 검수표만 만든다(정확도는 검수 후 `evaluate_list.py`).
- 합성 실험 결과는 실제 데이터 결과와 다른 표·키로 기록하고, 실제 성능 근거로 쓰지 않는다.
- 임계값·모델 선택은 모두 검증(val) 데이터에서 하고, 테스트에는 고정값을 한 번 적용한다.
